# 开发备注

给以后维护这个模块的人看的。使用说明见根目录 README.md。

## 一、编译

需要 JDK 17 或 21、Android SDK（platform 35、build-tools 35）。

1. 在工程根目录建 `local.properties`，写一行 SDK 路径，例如：
   `sdk.dir=C:/Users/你的用户名/AndroidSdk`
2. 设置 JAVA_HOME 指向 JDK（IntelliJ / Android Studio 自带的 jbr 也可以）。
3. 在工程根目录运行：

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`（已用 debug 证书签名，可直接安装）。
编好的安装包也放在 `release/` 文件夹，最新的是 `DoubaoA11y-1.1.2.apk`。

调试安装（电脑连手机）：

```bash
adb install -r release/DoubaoA11y-1.1.2.apk
adb shell am force-stop com.bytedance.android.doubaoime
```

## 二、查看日志

日志开关在设置页“调试选项”里，正式版默认全关。最基本的是“记录运行日志”（`runLog`），不开它 logcat 里只有警告和错误；其他几项控制记录的细节。也可以在电脑上直接打开，不用碰手机（豆包要在运行）：`adb shell am broadcast -a io.github.doubaoa11y.CONFIG -p com.bytedance.android.doubaoime --ez runLog true`。

LSPatch 没有模块日志界面，只能看 logcat（tag `DoubaoA11y`），用方法二。手机默认日志缓冲区只有 2MB，会很快被冲掉，先执行一次 `adb logcat -G 16M`（重启手机后要重设）。也可以双击 `tools/capture_log.bat`，它会自动加大缓冲区并把日志存到 `logs` 文件夹，按 Ctrl+C 或关窗口结束。

方法一（手机上，仅 LSPosed）：LSPosed 管理器 → 日志 → 模块日志，搜索 `DoubaoA11y`，可以用右上角菜单保存或分享日志文件。

方法二（电脑 adb）：

```bash
adb logcat -s DoubaoA11y
```

保存到文件：

```bash
adb logcat -s DoubaoA11y > doubao_log.txt
```

主要日志格式：

- `CreateView 窗口=xxx nativeId=… 宽=… 高=…`：原生层创建键盘视图。
- `drawText 窗口=soft_view "q"（字体=oimeui2023/w400 字号=… 对齐=0x5 颜色=… 区域=[l,t,r,b]）`：私有区字符写成 `\ue30b`，后面括号里是图标猜测，带问号的是待核实。
- `==== 键位表 #N（重绘后）… ====`：每个键一行，包括矩形、模块准备朗读的文字，下面列出主标签和角标。
- `悬停 窗口=… 悬停移动(7) x=… y=… 键=「q」[…]`：读屏模式下手指的位置和对应的键。
- `JNI DoCommit/5参 …`、`JNI notifyCandidateBarSnapshot/…`：原生回调和全部参数（数组只列前 12 项）。
- `键盘类型（键盘切换后）：getKeyboardType=… getCurrentKbdType=…`
- `注意：drawText 发生在 onDraw 之外`：如果出现很多，说明键位表的脏区清理方式需要调整，请告诉我。
- `签名不匹配` / `已降级` / `找不到`：豆包版本变化导致的问题，请把这几行发给我。

## 三、实现要点（1.5.3 实测）

- 签名已用 jadx 对照 1.5.3 核对，补充发现：
  - 图标字体有两套：oimeui2023 和 oimeui2025，分别对应两个字体资源；`createTypeFace(String, boolean, int)` 创建，模块 hook 它来记录字体名。
  - 公开的 `drawText(String, Typeface, int, int, int, boolean, float, float, Rect, boolean)` 和 `drawLinerGradientText` 最终都调用私有的 9 参数 `drawText`，模块按名称 hook 全部 drawText，用嵌套深度只记最外层一次。
  - fillRect 有三个重载：渐变（11 参）、单色单圆角（7 参）、单色四圆角（10 参）。
  - `getKeyboardType()` 返回 String，`getCurrentKbdType()` 返回 int。
  - `DoFunctionKey` 有 (int) 和 (int, String) 两个重载；`DoCommit` 有 3、4、5 参三个重载。
  - `onKeyboardBoardTypeChanged()` 只是把处理 post 到主线程（`lambda$onKeyboardBoardTypeChanged$49`），模块在那之后查询键盘类型。
  - CandidateItemView 继承的是 CandidateTextView（它再继承 TextView）。
  - 长按由 KeyboardView 内部 Handler 在 500 毫秒后发 `nativeTouch(id, x, y, -1, …)` 触发。
- 图标字体核对结果：
  - oimeui2023 = res/9U.ttf（U+E300–E3A1，153 个），oimeui2025 = res/c3.ttf（U+E900–E905，6 个：123、小写、大写、左箭头、删除、锁定大写）。
  - 字形名称没有语义（都是 uniE3xx），所以含义靠渲染图和皮肤样式里的用法核对。渲染图、皮肤摘录用 `tools/render_icons.py` 从自己的豆包安装包生成，放在本地 `docs/local/`（属于豆包的资源，不进仓库）。
  - 和最初目测表的主要差别：空格键画的是 e368（波形），e31c 只用在九键数字页的空格；中英切换键主标签是 e360“中”/e361“英”，e359/e358 是角标；Shift 三态 e310/e30e/e30f 正确；删除 e30b，按下时换成 e316；e390 是“手写查字”；e34a 是隐藏键盘；e37d 是笔画键盘的“折”。
- `tools/render_icons.py`：把 APK 里的图标字体渲染成对照图，并导出字形名称文本。
- 代码结构：
  - `ConfigSpec.kt`：设置项定义（设置页和 hook 共用）
  - `ui/SettingsActivity.kt`：设置页，用有序广播把设置发给豆包进程并取回状态
  - `hook/HookEntry.kt`：入口；`KeyboardViewHooks.kt`：绘制、触摸、悬停；`JniHooks.kt`：原生回调；`ServiceHooks.kt`：输入法服务和设置广播
  - `hook/DrawTable.kt`：键位表（脏区清理、按背景框归并文字、按坐标查键）
  - `hook/Speaker.kt`：用 HOVER_ENTER 事件朗读；`A11yState.kt`：读屏和触摸探索状态

- 讯飞式：豆包窗口根视图吃掉悬停事件，模块自己按坐标找键（`VirtualKeys.explore`/`targetAt`），朗读用无来源的 HOVER_ENTER 事件（`Speaker`），抬手时往 KeyboardView 注入合成 MotionEvent 输入；Java 控件给根视图派发一次点击（`tapView`），600 毫秒内压掉读屏的点击、聚焦事件。
- 触摸浏览关闭：拦截豆包窗口的 `ViewGroup.dispatchTouchEvent`，删除、空格、读屏面板、手写区原样交给豆包。
- 豆包菜单、剪贴板、常用语交给读屏焦点；被盖住的控件对读屏隐藏；`ToolboxPager` 把底部小圆点做成“下一页”/“上一页”按钮，双击翻页。
- 编辑面板：借用“单手模式”入口（`EditHooks`），面板放在 `keyboard_main_container_area` 里，按候选栏屏幕位置算上边距；打开时下面的自绘键盘不响应。
- 停留：删除、空格提前注入按下，让原生 500 毫秒长按刚好落在设定时间（`deleteHoldMs`、`spaceHoldMs`）。
- 键盘收起提示：豆包自己收起走 `requestHideSelf`，立即读；返回键、滚动收起由应用侧先做动画，豆包最早收到 `InputMethodImpl.updateEditorToolType`（比 `hideSoftInput` 早约 0.44 秒），弹出时也会先来它但紧跟 `showSoftInput`，所以延迟 80 毫秒、来了 `showSoftInput` 就取消。
- 设置项：`ConfigSpec` 里 `Group.FIXED` 的项不在设置页显示，`Config.b` 永远返回默认值。
- 版本提醒：豆包 versionCode 和 `TARGET_VERSION_CODE` 不同时，设置页状态开头读“注意”，键盘第一次弹出读一次提醒（每个版本只读一次，记在 `warnedVersion`）。

## 四、已知的技术问题

- 讯飞式下双击不会按键，焦点在编辑框上，双击点的是编辑框。
- 按钮中文名是按豆包的资源 id 起的，少数可能不准。
- 上滑字符是按“主标签上方的小字”推断的。
- 键盘编号按 1.5.3 实测整理，没见过的键盘读成“键盘 加编号”。
- 模块刚启用时会请求键盘整屏重画一次来建立键位表；如果键位表是空的，收起键盘再弹出一次。
- 触摸浏览关闭时，豆包自带的滑动手势（上滑输入符号、滑动删除）不能用。
- 字节风控库 libmetasec_ml.so 是否检测 Xposed 或签名变化还不清楚。

新增：

- 读屏开着、但触摸浏览关着时，键盘仍然按讯飞式操作：手指按下、滑动时读出手指下的键，抬起时输入。候选栏、工具栏也一样。
- 这种情况下删除键和空格键沿用豆包原来的触摸：按下就读键名，然后完全交给豆包，长按连删、长按语音、空格上滑动等都是豆包自己的行为。
- 这种情况下，豆包菜单、剪贴板、常用语完全用豆包原来的触摸，模块不处理。
- 豆包自带的滑动手势（上滑输入符号、滑动删除等）在这种情况下不能用，因为手指移动被当成了“摸”。
- 设置页“触摸浏览关闭时仍用读屏操作”可以关掉，关掉后就是豆包原来的直接触摸。读屏关掉时不生效。

- 长按空格说话时可以滑动：左上方“松手撤回输入”，右上方“松手一键发送”，中间“松手结束”。

阶段 4 新增：

- 切换键盘时读出新键盘的名字：全键拼音、九键拼音、英文键盘、符号键盘、数字键盘、数字符号键盘、手写键盘、笔画键盘。中英切换也是这样提示（全键拼音 / 英文键盘）。
- 按 Shift 后读出新的状态：小写、大写、锁定大写。
- 设置页“键盘弹出时朗读当前键盘”可以打开，默认关闭；“切换键盘、Shift 大小写时朗读提示”可以关掉。
- 键盘编号是按 1.5.3 实测整理的，没见过的键盘会读成“键盘 加上编号”，遇到请告诉我。

阶段 3 新增：

- 打拼音时自动读第一个候选，单字会带解释，比如“高，提高的高”。
- 候选栏、工具栏、更多候选面板也改成讯飞式：手指滑过去就读，抬手就选中或点击，读屏焦点仍然留在编辑框。
- 单字解释用 jieba 分词的开放词频表（MIT 许可）生成，每个字配一个最常见的词，生成脚本是 `tools/build_char_words.py`。
- 设置页可以分别关掉“朗读第一个候选”和“单字解释”。
- 逐字解释的字数可调：候选不超过设定的字数时，每个字都解释，比如“高兴，提高的高，高兴的兴”；选“全部逐字解释”就是不限字数。默认只解释单字。
- 豆包菜单交给读屏处理：打开后焦点自动落到第一个项目，左右滑动逐个浏览；滑过一页的最后一个项目会读“下一页”，并自动翻页、聚焦下一页的第一个项目。最后一页之后回到第一页。
- 剪贴板、常用语也交给读屏处理，打开后焦点落到第一个项目。这类界面打开时，被它盖住的工具栏和候选栏对读屏隐藏。
- 中文键盘的字母读小写（以前读屏会读成“大写G”），英文键盘按键面上的大小写读。
- 逐字解释只用于候选词，提示文字不再逐字解释。
- 九键、数字键盘左边的符号栏：每个符号单独读；手指停在最下面一格 0.8 秒会自动往下翻，停在最上面一格会往回翻，翻完读出手指下面的新符号。（0.4.3 试过改成读屏焦点，效果不好，已撤回。）
- 修正：符号栏滚出去、被裁掉的符号不再算键（以前候选栏左边会误读成“加号”）。

阶段 2 的用法（默认是讯飞式）：

- 读屏焦点一直留在编辑框，不会跳进键盘。
- 手指在键盘上滑，摸到哪个键，模块就读哪个键。
- 抬手输入：手指停在键上直接抬起，就输入这个键。手指滑出键盘再抬起，不会输入。
- 删除键：手指停住 1.5 秒后开始连续删除，抬手停止。
- 空格键：手指停住 1 秒后开始语音。说话时手指可以移动：滑到左上方读“松手撤回输入”，滑到右上方读“松手一键发送”，回到中间读“松手结束”。抬手就按当前位置执行。
- 设置页关掉“讯飞式”后，每个键都会成为读屏焦点，抬手或双击由读屏自己负责，模块不再重复输入。
